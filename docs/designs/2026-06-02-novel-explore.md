## 一、为什么需要它（缺口诊断）

现有七 skill（`novel-concept/setting/character/outline/style/consistency` + `novel-runtime`）有两个共同特征：

1. **收敛**：每层都把模糊感觉**逼向一个答案**（定义一份契约 / 一份大纲 / 一份风格实例）。
2. **负向防护**：runtime 的质量闸、⑤ 猎缺陷、⑥ 一致性底账、指纹 daemon —— 全在测"**别漂移 / 别写崩 / 别有硬伤**"。

它们都**假设你已经知道要什么**。但创作早期最真实的状态是"**我有品味、但说不清抽象参数**"。这正是 bake-off（铺开多个版本让人选）最强的场景，而现有体系完全没有这一姿态。

**而锚点的"消费端"已经建好了**：⑤ 样例锚（`novel-style` 模式二）+ runtime 装配会把"选中的样板正文"钉进每章 prompt，ch2+ 还自举。缺的只是它**上游的"发散生成 + 人来选"**。

> 一句话定位：`novel-explore` 是七层的**发散孪生**，坐在最上游；它不产出最终文本，只产出**被选中的锚**，喂回各层的实例文件 / runtime 装配单。

## 二、核心原则（为什么契合项目 DNA，而非硬塞）

| 原则 | 说明 | 同源 |
|---|---|---|
| **AI 只发散，人决策** | skill 绝不排名 / 推荐"哪个最好"，只铺选项 + 点差异 + 让人选 | 质量闸"不让 AI 评好坏"、读者口"不做模拟" |
| **发散要张成空间，不是换皮** | 强制沿一条**有意义的分叉轴**生成（代价高低 / 谁是反派 / 主动被动），否则得到 3 个近义物 | workflow diverse-lens / judge-panel |
| **反仪式** | 三条判据全中才 bake-off：① 有多个都不错的不同答案 ② 有品味说不清 ③ 锚定大量下游 | 消融路线图"剪死没用的层" |
| **锚必须落盘** | 方向锚填进 ①②③④ 实例文件；质感锚写进 runtime 装配的样例锚块；**决策记录（`docs/explore/<书>-decisions.md`）是 explore 自己的归档流水账，不被 runtime 装配读取** | ⑤/④ 的"命名实例文件"模式 |

> **澄清（架构评审 🔴；v0.3 再校正）**：质感锚 sink 被纠正了两次——① 早期草稿写"⑤ 样例锚槽"是错的（`novel-style` 实例[八维+禁忌+试金石]**没有"样例锚"字段**）；② v0.2 改指"runtime template §2 装配单那一行"**也不准**——亲查 `novel-runtime/template.md` §2 装配单表只有 8 行、**没有样例锚行**；样例锚只作为散文条目活在 `novel-runtime` **SKILL §装配配方**里。**准确说法**：质感锚落点 = runtime 装配的**样例锚块**（SKILL §装配），既不是 ⑤ 实例、也不是 template §2 的某一行。**顺带暴露**：runtime 自己 SKILL（讲了样例锚）↔ template §2（漏了样例锚行）有处既有不一致——explore 落地时给 §2 补一行"样例锚"即可一并补上。

## 三、三种锚 × 可发散点全景（主表）

锚分三类 —— 这个分类直接决定**选中后落到哪、怎么落**（"落盘动作"列是 v0.2 新增，对应每行第 4 格）。

### A. 方向锚 — 选"走哪条路"，落到 ①②③④ 实例

| 可发散点 | 出什么多版本 | 落到哪 · 怎么落 | 价值 |
|---|---|---|---|
| 金手指 + logline | 不同机制 × 强度/代价曲线 | ①concept · 填 §1/§3/§4 字段 | 🔴 最高（定错全推倒） |
| 主角三位一体 | 不同原型 × 与金手指的化学反应 | ③character · 填角色卡字段 | 🔴 高 |
| 力量体系骨架 | 不同台阶隐喻 + 世界中心张力 | ②setting · 填体系字段 | 🟡 中高 |
| 分卷走向 | 一条主线的几种展开分支 | ④outline §2 · 填分卷骨架 | 🔴 高 |
| **开局策略**（含前 3 章追读钩） | ch1 金手指怎么登场、第一钩子类型、前 3 章信息释放节奏 | ④开局特护 §4 · 填关卡落点 | 🔴 极高 |
| **断章/章末钩子** ⟵v0.2新增 | 危机断 / 悬念断 / 反转断 / 信息揭晓断 | ④章纲 · 填章末 | 🔴 高（连载追读核心） |
| **金手指首次爽点兑现** ⟵v0.2新增 | 第一次爽怎么给（打脸/换命/碾压） | ④开局（前 10 章小爆点）· 填节拍 | 🔴 高 |
| **卷末爆点选型** ⟵v0.2新增 | 突破/复仇/揭秘/反转，踩第几章 | ④分卷（卷末高潮）· 填四件套 | 🟡 中高 |
| 单章剧情走法 | 给定章纲的几种戏剧化（卡文时召唤） | ④章纲 · 临时供选，可不落盘 | 🟡 中 |
| 感情线走向 | 谁和谁、怎么推进（言情/CP 大分叉） | 主 sink ③关系网 · 填③ + 校 ④ | 🟡 中（看赛道） |
| 爽点配方 ⟵v0.2改 | 已定金手指+气质下的**兑现密度/节奏**（非平铺选爽点类型） | 主 sink ⑤维度C · 填⑤ + 校①强度曲线 | 🟡 中 |

> **双 sink 行的落盘动作（架构评审 🟡5）**：感情线、爽点配方落两个文件时，按"先写主 sink、再校副 sink 既有对齐不被打破"执行（如爽点配方先写 ⑤维度C，再校 ① 强度曲线一致），不要两边各改一半导致 concept↔style 接口失谐。

### B. 质感锚 — 选"读着对的文字"，落到 runtime 装配·样例锚块（用户原话"写几个片段"）

| 可发散点 | 出什么多版本 | 落到哪 · 怎么落 | 价值 |
|---|---|---|---|
| **文字质感试写**（与"开篇段落"合流，**必须用本书真实开篇/爽点场景**，不用中性练习场景） | 同一开篇场景 N 种笔触 → 选中成 ch1 锚 | runtime 装配·样例锚块 · 替换（顶替 ch1 默认的"参照作品片段"） | 🔴 极高（解决"只能借参照书"） |
| **开篇段落** | 第一段的几种写法（钩子+文字一体，且要扛住"金手指 2000 字内现身"铁律） | runtime 装配·样例锚块 + ④开局 · 替换+填开局 | 🔴 极高（决定留存） |
| 名场面写法 | 突破/对决/反转/初遇等高光时刻的演绎 | runtime 装配·样例锚块（拐点重置）· 替换 | 🟡 中 |
| 命名调性 | 古雅/直白/中二三选一 → 之后所有专名按它生成 | ⑥名词表·命名约束 · 写约束字段 | 🟡 中（巧：一次定调管全书；**存疑·待汰**：近三元小选择，未必需重型协议） |
| 视角试写 | 同开场写成第一/第三人称、单/多线 | ⑤维度A · 填维度A | 🟡 中（**存疑·待汰**：网文 95% 第三人称跟随，作者少纠结） |
| 角色口癖 | 同角色几种说话方式（写 3 段对白） | ③口癖字段 + ⑤ · 填③口癖 | 🟢 低-中（**存疑·待汰**：下游窄、与③/⑤重叠） |

### C. 卖相锚 — 选"怎么卖"，落到决策记录（纯归档，补搁置的 ⑦ 市场层）

| 可发散点 | 出什么多版本 | 落到哪 · 怎么落 | 价值 |
|---|---|---|---|
| 书名 | N 个候选（网文点击第一道门） | decisions.md · append（**不进装配**） | 🟡（**存疑·待汰**：不锚下游，违判据③；要书名其实一句话问 AI 即可，不必走完整协议——保留仅因开书前确有此需求） |
| 简介/文案 | N 版开篇文案 | decisions.md · append | 🟡（**存疑·待汰**，同上） |
| 章节标题 | 吊胃口 vs 直白 | decisions.md · append（连载期轻量） | 🟢 低（**存疑·待汰**：边际最低） |

> **关于"存疑·待汰"（用户定：不砍）**：上面标注的低价值档位**全部保留**，但诚实记号——它们用本设计自己的三条判据衡量偏弱（多卡在"锚定大量下游"）。**保留不删**，遵循项目"未实测不删"原则（同 ⑤ 维度绑定审计：弱证据不动框架）；等消融/实战量出它们确实是仪式，再回头汰。

### 哪里别用（铁定不 bake-off）

- **⑥ 一致性登记**：机械抽取 + 人工确认，没"选哪版"余地。
- **逐个专名 bake-off**：浪费 —— 只 bake 命名**调性**一次，之后按调性生成。

## 四、发散协议（高度无关的引擎）

"不止三档、都考虑进去"的正解：**别给每个档位写一套逻辑**（会爆炸），而是 **一套协议（永不变）+ 一张档位登记表（可加行）**。

> **v0.2 校正（架构评审 🟡4）**：协议**前 4 步**（逼轴→铺→点差异→人选）确实**高度无关**、对所有档位通用——这部分抽象成立。但**第 5 步"落盘"不是单一模板，而是按锚类型分流的 dispatch**（填字段 / 替换样例锚块 / append 归档）。所以档位登记表必须有第 4 格"落盘动作"，否则跨文件写一致性问题会被糊掉。

### 发散协议

1. 聊清这个决策点，**逼出一条有意义的分叉轴**（这是含金量所在，也是最大风险点 —— 提炼不出真轴就会退化成换皮，见 §八）。
2. 沿轴**并行**铺 3-4 个**真正不同**的版本（diverse-lens；考虑用 workflow `parallel` 跑）。
3. **点出版本间差异**（你在比什么），**绝不排名 / 推荐**。
4. 用户选（允许混搭："要 A 的设定 + B 的口吻"）。
5. **落盘成锚**（按锚类型分流）：方向锚→填对应 ①②③④ 实例字段；质感锚→替换 runtime 装配的样例锚块；卖相锚→append `docs/explore/<书>-decisions.md`。无论哪类，都同时在决策记录追加一条流水（选了什么 / 为什么）。

### 档位登记表（每行四格，加档位 = 加行，协议一行不动）

| 档位 | "一个单位"长啥样 | 分叉轴候选 | 落盘动作（sink · 怎么写） |
|---|---|---|---|
| 金手指 | 一句 logline + 机制段 | 机制类型 / 代价轻重 / 成长曲线 | ①concept · 填 §1/§3/§4 字段 |
| 开局策略 | 一份"ch1 怎么开 + 前 3 章节奏"方案 | 第一钩子类型 / 金手指何时现 / 信息给多少 | ④开局特护 §4 · 填关卡落点 |
| 文字质感 | 一段开篇真实场景 ~300 字 | 句长 / 抒情度 / 视角距离 | runtime 装配·样例锚块 · 替换 ch1 默认 |
| 书名 | 一个 4-8 字标题 | 直白↔意象 / 爽↔雅 | decisions.md · append（不进装配） |
| …（其余档位照填四格） | | | |

## 五、连载期接口（不只 t=0）

explore 不是开工用一次就扔，连载期三个时机随时召唤：

1. **拐点**（换 POV / 新卷转调）→ 重试**质感锚**（重置 runtime 装配样例锚块，介入后 ch2+ 自举从新锚续起）。
2. **卡文** → 给单章开多版本走法（A 类"单章剧情走法"）。
3. **套路疲劳处方**（连载追读的结构性防线）：
   - **当下可用信号**：⑤ 猎缺陷清单里**已存在**的"套路疲劳"人工条——explore 现在就能接它，开几个"换个 beat"的处方让人选。
   - **future 信号**：质量闸路线图**梯队三结构指纹**（自动检测结构同质），其处方按路线图设计"把看板第 2 图（节拍/爽点分布）从被动观测变成主动约束"。但结构指纹**门槛 = 过 ~20 章 且 消融证明结构有用再建**，现在不存在。
   - **未落地的依赖（架构评审 🟡6）**：无论信号来自哪，`novel-runtime` 的 tick 目前**没有"接收外部处方并改写下一章 beat"的步骤**（tick 现有流程的骨架是 extract→commit→feed-forward）。这个接入步骤要新增——登记为 future，排在第七节阶段 4。

> **连载 vs 日更的姿态（网文评审 #16）**：bake-off 多版本与"日更 1-1.5 万字"的速度正面冲突，必须分两档——**开书前（t=0）一次性密集 bake-off**（开局/金手指/质感锚/书名，定一次管很久，值得花时间）；**连载期只在"真卡住"时单点召唤**（卡文 / 换 POV / 卷末爆点），且**版本数压到 2 版**（日更没空挑 4 个）。不区分会让连载误以为每章都要发散，变成太监加速器。

## 六、与现有层的边界（防打架）

| 易混 | explore 的职责 | 现有层的职责 |
|---|---|---|
| 样例锚 | **产**（试写多版本 + 选中） | runtime 装配**消费**（钉进 prompt）+ 自举替换。explore 不重造钉锚逻辑 |
| **ch1 锚来源** ⟵v0.2新增 | 有 explore 试写 → 选中片段**顶替** ⑤ 默认的"参照作品片段" | 无 explore 时回退 ⑤ 原逻辑（`novel-style` 行 102）；ch2+ 自举仍归 runtime，explore 仅在拐点显式重置，介入后自举从新锚续起。**落地需在 `novel-style` 那条 ch1 规则上留"或由 explore 提供"接口** |
| 大纲分支 | **发散**几条走向供选 | ④ 把选中的走向**落成**完整三级大纲 + 校验 |
| 决策记录 | 跨档位的"选了什么 + 为什么"流水账（**纯归档，无 skill 消费**） | 各层实例文件是"选定后的成品契约"，不记备选 |
| 卖相（书名/简介） | 发散 + 选 + 记进决策记录 | ⑦ 市场层仍**不做完整契约**，决策记录就是它的轻量落点 |

## 七、建造顺序（分批，符合"先有尺子再加功能"）

| 阶段 | 落地物 | 验证什么 |
|---|---|---|
| 1 | 发散协议 + 档位表骨架（含"落盘动作"列）+ **开局策略 + 开篇场景质感试写（合流）** + 金手指/logline（地基同批）+ `decisions.md` 的 template/example | 协议前 4 步跨档位通用 **且 落盘真咬合**：质感锚选中片段能写进 runtime 装配的样例锚块、顶替 ch1 默认；金手指选中版能填进 concept 字段且不破坏 §5 龙头接口 |
| 2 | 补 A 类（力量体系/主角/分卷/感情线/爽点配方[改]）+ **新增（断章钩 / 金手指首次兑现 / 卷末爆点）** | 方向锚批量复用协议 + 落盘分流 |
| 3 | 补 C 类卖相锚（书名/简介/章节标题）+ B 类其余（视角/命名调性/口癖/名场面） | 剩余 B/C 类档位（含低价值/存疑者）实战检验是否值得正式化 |
| 4 | 接 runtime（套路疲劳处方，含 tick 新增"处方接入"步骤） | 待结构指纹落地后启用；当下先接 ⑤ 猎缺陷人工条 |

> **v0.2 重排理由（网文评审）**：原阶段 1 是"文字质感 + 金手指"，被指出搞反了优先级——**开局是第一生死线**（金手指选错能在连载中调强度曲线，前 3 章把读者赶走无法挽回；项目硬事实：签约门槛前 1-2 万字、太监率全平台 90%、开局特护"前 3 章密度 > 前 30 章总和"）。且文档把"开篇段落"自标 🔴极高却推到阶段 2，自相矛盾。故阶段 1 改为"开局策略 + 开篇场景质感试写"——后者正好让"质感锚探针"（架构关切）与"开局优先"（网文关切）合流：用真实开篇场景做质感试写，一举两得。

## 八、未决 / 风险

- **最大风险：分叉轴提炼**。整个 skill 的价值押在协议第 1 步能否逼出"真轴"而非换皮轴。无银弹，只能靠协议强约束 + 例子示范，且**质量判断只能靠人当场识别**（AI 不许自评——项目铁律）。证伪挑战指出此处有循环风险（能判轴真假者未必需要 bake-off）；缓解 = 把"识别差异"降到具体文本层（读 3 段能否感到有意义的不同），而非要求用户先抽象描述。建造阶段 1 就要拿真案例压测这一步。
- **（评审 #11）"多版本选" vs "改写 pass 不重 roll" 的张力**：explore 的核心前提（出多版本让人选）表面与项目已固化的"改写 pass 不重 roll"（F7）相反。**调和**：二者管**不同阶段**——"不重 roll"用在**收敛期**（已有目标=章纲/契约，改一稿更准、重 roll 反而引随机漂移）；bake-off 用在**发现期**（还没有目标可"改向"，只能铺开、发现、再选）。同一动作（多生成）在有靶子时是浪费、在找靶子时是唯一出路，故不矛盾。**但诚实记账**："发现期多版本选 > 单版迭代"目前**零证据**——列为待测，阶段 1 探针顺带验（开局质感试写时对照"多版本选" vs "写一版 + 反应"）。
- **（选项 c）explore 与消融是上下游、非正交**：explore 的产出喂回 ①②③④⑤ + runtime，而这些层正是质量闸消融要审"是否仪式"的对象。**若消融判某下游层（尤其样例锚 / 大纲）为仪式，explore 对应的"🔴 极高"档位当场作废**。因此：开写前帮选方向、且不沉淀 runtime 的档位（logline 方向 / 书名）消融管不到，可先推进；**喂回 runtime 的档位（质感锚 / 大纲分支）依赖消融结论**，推进时心里有数。
- **生成成本**：多版本 = N× token。质感/开篇试写尤其贵（每版一段正文）。用 workflow `parallel` 还是 skill 内顺序，建造时定（倾向顺序起步）。
- **决策记录 schema**：阶段 1 定（至少：日期 / 档位 / 分叉轴 / 候选列表 / 选中项 / 选择理由 / 落盘去向）；对齐其余 skill 的 template+example 三件套惯例。
- **tick 处方接入步骤**：连载期套路疲劳闭环依赖一个 tick 里尚不存在的步骤（见 §五），排阶段 4。
- **低价值档位待汰**：§三 标"存疑"的若干档位保留不删，等消融/实战裁定（未实测不删）。
