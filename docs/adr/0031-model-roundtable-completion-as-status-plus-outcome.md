# Model roundtable completion as status plus outcome, not an overloaded `completed`

agent-roundtable currently has one lifecycle field, `status: active | paused | completed`. Several materially different end states are all compressed into `completed`: a normal finish, a human `stop`, a finish where some providers failed, a finalizer failure, a total failure, and a crash-recovered finish. The 2026-07-30 fixes kept the "`completed` ⇒ `summary.md` exists" invariant by writing an explanatory fallback summary on failure and on no-runner stop — which preserves the invariant but leaves the distinction only in prose inside the summary, not machine-readable.

We will separate the run-state axis from the result axis: `status` continues to describe where the topic is in its lifecycle (`active | paused | finalizing | completed | cancelled`), and a new `outcome: success | degraded | failed` describes how it ended. A human `stop` becomes `status=cancelled`; a finish where the finalizer or some providers failed becomes `status=completed, outcome=degraded|failed`. The summary stays the human-readable explanation; the fields become the machine-readable truth that `render`/`list` and any future consumer can read without parsing prose.

We accept that this adds a field and touches the status transition table, `render`, and `list`. That cost is small and is paid now because these surfaces already want to show the distinction, and because compressing outcomes into `completed` is exactly what made the "fake completion" bug (no-summary `completed`) possible in the first place. This supersedes the interim choice in the #8 fix, which deliberately avoided introducing `cancelled` to minimize churn.
