# 小说开工准备包 · 全景

> 写一本(凡人式)修仙网文，动笔前要备好哪些**契约文件**？本文是这些层的索引 + "框架/实例分离"原则 + 逐块建造路线图。
> 配套：风格层已落地为 `skills/novel-style/`。创作流程的 12 阶段细节见 `2026-05-19-网文创作流程与AI角色映射.md`（本文不重复，只补"准备契约"这个角度）。

## 背景：为什么需要这份全景

八维风格契约只覆盖了**一层**——"怎么写、读起来什么感觉"。它故意不回答"写什么 / 写谁 / 按什么顺序写"。要真正开写，需要**一组正交的准备契约**，风格只是其一。本文把这组契约列全，并规划怎么用和 `novel-style` 同样的"模板 + 命名实例"模式逐块建出来。

---

## 核心原则

1. **正交分层**：每层回答一个互不重叠的问题，层与层解耦。正交才能复用——同一套世界观能配不同风格，同一种风格能套不同金手指。
2. **框架 / 实例分离**：每层都做成"稳定模板（schema）+ 可换命名实例"。换设定/换气质 = 换实例，框架不动。（同 `novel-style` 的 `template.md` + `examples/*`。）
3. **依赖顺序**：有的层是地基（定错全推倒），必须先定；有的层正交、可晚定。见下表"依赖顺序"列。

## 各层详解（"准备契约"角度）

> 每层只写：**回答什么 · 契约怎么 schema 化 · 与别层的接口**。详细创作方法论见研究文档对应小节。

### ① 创意层 — logline + 金手指（地基）
- 详见研究文档 §1.2。
- 契约化：`logline`（主角+金手指+主线冲突一句话）+ `金手指`（类型/机制/强度曲线/代价）。
- 金手指类型有套路库（系统/签到/模拟器/重生/复制…），可做"类型模板 + 本作实例"。
- **接口**：金手指决定 ③ 主角性格、④ 爽点节奏、⑤ 风格 C(节奏) 的取值。定错全推倒。

### ② 设定层 — 力量体系 + 世界观（命脉）
- 详见研究文档 §1.3。
- 契约化（最适合 schema）：力量体系 = `台阶序列 + 每阶晋级条件 + 每阶能力量化(移山/御空/灭城…)`；外加地理势力图、时代背景、设定 wiki。
- **接口**：力量台阶是 ④ 大纲升级节奏的标尺，是 ⑥ 名词表的来源。

### ③ 人物层 — 角色卡（与风格衔接最紧）
- 详见研究文档 §1.4。
- 契约化：每角色一张卡 = `基本信息/性格/动机/口癖/弧线/关系网`；反派要有逻辑闭环。
- **强约束**：研究文档强调的**主角人设 × 金手指 × 爽点三位一体**住在这一层（联动 ①）。
- **接口 / 重叠**：见下方"重叠与边界"——主角卡 vs 风格维度 B 要切干净。

### ④ 结构层 — 大纲（依赖 ①②③）
- 详见研究文档 §1.5 / §1.6 / §1.7。
- 契约化：`总纲(主线+主角弧线)` → `分卷大纲(每卷:开篇钩子+2-3中段爆点+卷末高潮)` → `章纲(每章:钩子+爆点)`。卷/章的钩子结构可模板化。
- **接口**：消费 ①②③ 的产出，产出喂给章节生成（连同 ⑤ 风格前缀）。

### ⑤ 风格层 — 八维风格契约
- 详见 skill `skills/novel-style/`（八维框架 + 注入/审计三模式）。
- **接口**：维度 B 承接 ③ 主角投影；维度 C 承接 ①② 的升级速度；维度 F 定 ② 世界规则的阅读温度。**不再往八维加维度**（会污染框架稳定性）。

### ⑥ 一致性底账 — 两张表（边写边维护）
- 详见研究文档 §五 方向 C（不做完整引擎，只维护角色状态表 + 设定名词表）。
- 铁律：LLM 只抽候选、人工确认才入库（70-80% 准确率）。
- **接口**：状态来源于 ②③，随 ④ 正文推进更新。

> 各层落地状态（已建 skill / 实例 / 模式）见文末"当前状态"，不在此重复。

### ⑦ 市场层 — 定位（可选，但建议先想）
- 详见研究文档 §1.1。
- 不一定做成契约文件，但平台/赛道/读者画像会**反向决定** ① 金手指强度、⑤ 风格的节奏/爽点密度取值。至少先想清楚再定 ①⑤。

## 重叠与边界（防止两份文件打架）

| 易混点 | 归属 | 切法 |
|---|---|---|
| 主角性格 | ⑤维度B **只取影响文字气质的轴**（理性↔冲动、隐忍↔张扬）；③主角卡是完整全身像（姓名/外貌/动机/弧线/关系） | 维度 B = 主角气质的"投影"；主角卡 = "全身像"。校准顺序：先定主角卡，再投影到维度 B |
| 人设×金手指×爽点三位一体 | ①创意层 + ③人物层 | 不属于风格层。风格只承接它的"气质投影" |
| 节奏/爽点 | ⑤维度C(怎么写出节奏) vs ④结构层(在哪一章给爆点) | 风格定"密度/驱动模型"，大纲定"具体卡点位置" |
| 力量台阶 | ②设定层(定义台阶) vs ⑥名词表(登记已用) vs ④大纲(安排何时突破) | 一处定义、一处登记、一处调度，不重复定义 |

## 补建：运行时层（2026-06-01 第二轮）

**诊断（为什么要补）**：六层准备包全是 **design-time 静态契约**，但一本书 99% 工作量在"正在写第 247 章"——effort 和风险位置是反的。证据自洽：唯一实测坏掉的（语言劣化）是运行时现象；缺口（控制环/上下文装配/伏笔回收/可观测）全是运行时；验证只做到第 1 章（最容易处）；审计只验 conformance 不验 outcome；阅文抄不动的差异化（整书一致性）也正是"书尺度的运行时"。
