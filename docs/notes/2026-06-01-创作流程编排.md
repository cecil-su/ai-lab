# 创作流程编排 · 六 skill 如何串成管线

> 目的：把六个准备包 skill（`skills/novel-*`）串成一条可操作的创作管线，并映射到研究文档 §五 方向 A 的子代理。
> 范围：本文是**流程规格**，不是可执行编排器。把它升级为脚本/多 agent 编排，应在 M0 通过（见 `2026-06-01-M0竞品深拆.md`）之后再做——避免抢跑产品建设。

---

## 一、三阶段管线

```
┌─ 阶段一：开工前·设计（一次性，框架契约）────────────────┐
│                                                          │
│   ① 创意(novel-concept)  ← 地基,最先定                    │
│        │ 金手指牵动全局                                    │
│        ├──────────────┬──────────────┐                   │
│        ▼              ▼              ▼                   │
│   ② 设定(setting)   ③ 人物(character)  ⑤ 风格(style)      │
│   力量体系          角色卡            八维契约            │
│        │              │ §7投影→⑤维度B   │ ③定后校准      │
│        └──────┬───────┴───────┬────────┘                 │
│               ▼               ▼                          │
│          ④ 结构(outline) 消费①②③⑤,排章节               │
└──────────────────────────────┬───────────────────────────┘
                                ▼
┌─ 阶段二：开工·建账（一次性）──────────────────────────┐
│   ⑥ 一致性(consistency) 建空表,按②③填初始状态           │
└──────────────────────────────┬───────────────────────────┘
                                ▼
┌─ 阶段三：连载循环（每章重复）──────────────────────────┐
│   1. 查 ⑥ 状态表/名词表（韩立现在几境?名字用过没?）       │
│   2. 注入：⑤风格前缀 + ③角色卡 + ②设定 + ④本章章纲       │
│   3. 生成本章正文                                         │
│   4. ⑤审计：试金石 + 八维 + 禁忌（跑味就回 3）            │
│   5. ⑥抽候选 → 人工确认 → 更新状态表/名词表              │
│   6. → 下一章回到 1                                       │
└───────────────────────────────────────────────────────────┘
```

**依赖要点**：
- ① 是地基，定错全推倒，**必须最先**。
- ②③⑤ 并行，但 **⑤ 维度 B 要等 ③ 主角卡定后校准**（投影一致）。
- ④ 消费 ①②③⑤，**最后设计**。
- ⑥ 开工时建空表，之后每章维护。

## 二、skill ↔ §五方向A 子代理映射

| 准备包层 | 本仓库 skill | 研究文档 §五 子代理 | 在管线里的角色 |
|---|---|---|---|
| ① 创意 | `novel-concept` | （创意/logline，§五未单列，属前置） | 定金手指，喂全局 |
| ② 设定 | `novel-setting` | 设定 agent（worldbuilder） | 力量体系/势力 |
| ③ 人物 | `novel-character` | 角色 agent（character tracker） | 角色卡 |
| ④ 结构 | `novel-outline` | 大纲 agent（plot architect/outliner） | 总纲/分卷/章纲 |
| ⑤ 风格 | `novel-style` | 章节 agent 的**风格特征注入**部分 | 注入 + 审计 |
| ⑥ 一致性 | `novel-consistency` | 一致性 agent（事后审查模式） | 查表 + 抽候选 |
| （生成） | —（阶段三第 3 步） | 章节 agent（scene/chapter writer） | 产出草稿供人类改写 |

> 合规定位（研究文档 §1.9）：章节 agent **生成草稿供人类改写，不直接发布**；标识 agent（§五）在阶段三末尾追加 AI 辅助标识。

## 三、已验证的管线证据（来自本轮端到端测试）

- **注入有效**：八维压成 9 行前缀，生成正文 8 维全中、禁忌零触犯（`2026-06-01-fanren端到端验证-第1章.md`）。
- **接口咬合**：①金手指约束 → 正文回避白给；③人设 → 情节选择；⑤节奏 → 开局不写打脸。
- **连续生成漂移**：人设/节奏/世界观 3 章不崩，但**语言层重复**（章末趋同+高频词）漂移最快（`2026-06-01-fanren连续生成-劣化测试.md`）→ 管线阶段三建议在第 2 步注入时追加一条 negative 指令"避免与最近 3 章相同的章末收束与高频词"，或在 ⑥ 加一张"已用桥段/收束"表。

## 四、升级为可执行编排的前置条件

1. **M0 通过**（差异化空间确认，见竞品深拆——已初步通过，候选 2/3 待人工实测补强）。
2. 决定形态：Claude Code 多 skill 手动串（轻）/ 脚本编排（中）/ 多 agent 自动管线（重）。
3. **质量兜底必备**：⑤审计 + ⑥人工确认入库是硬环节，不可全自动（LLM 自审偏高、抽变更 70-80% 准确率）。

> 在此之前，六个 skill 已可**手动按管线顺序调用**完成一本书的开工准备 + 单章生成验证。
