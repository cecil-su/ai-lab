## 一、创作生命周期（12 个阶段）

### 阶段速览

### 1.1 市场定位

- **平台差异**：
  - 起点（男频付费）：玄幻、都市、科幻、历史，重订阅、重月票，VIP 章节按 3000 字算一章（均订计算口径），主流书章节 3000–5000 字
  - 番茄（免费、按曝光分成）：爽点密度极高、节奏极快，章节长度与起点相近但**日更量更大**（工作室常 8000+ 字/天），题材门槛低
  - 晋江（女频付费）：言情（含 BL/纯爱）、古言、现言，重剧情节奏与角色塑造
  - 七猫（免费）：下沉市场、土味流派接受度高、章节短
- **赛道选择三要素**：自己读得最熟的流派 + 当前数据上行的子赛道 + 自身金手指设计能力
- **读者画像**：年龄段、性别、阅读时段、付费习惯

### 1.2 核心创意（点子）

- **logline**：一句话能讲清"主角是谁 + 金手指是什么 + 主线冲突是什么"
- **题材 / 流派**（"写什么"）：玄幻、都市、科幻、历史、无限流、规则怪谈、克苏鲁、末世、星际…
- **金手指 / 机制**（"靠什么爽"）：系统流、签到流、模拟器、穿越/重生、复制天赋、苟道流、无敌流、扮猪吃虎…
  - 题材决定背景，机制决定爽点来源。两者正交，组合才形成具体设定（例：「都市 + 系统流」「玄幻 + 模拟器」）
- **金手指强度曲线**（最容易翻车）：
  - 太强：开局即无敌，中后期写不出张力（无敌流的难点）
  - 太弱：升级太慢，读者弃书（爆肝流的难点）
  - 主流解法：金手指有"成长性"或"代价"——签到流要靠时间累积、模拟器有次数/资源限制、系统流给任务但不直接给结果
- **避坑**：金手指一旦定下，整本书的爽点节奏都跟着它走，定错=推倒重来

### 1.3 世界观与体系

- **力量体系（最重要）**：
  - 要有"清晰的台阶"——读者要能数清主角升了几级
  - 经典层级：练气→筑基→金丹→元婴→化神 / 武者→宗师→大宗师→武圣
  - 每个阶段对应可量化的能力提升（移山、御空、灭城…）
- **地理与势力**：主大陆、势力图、组织关系
- **设定 wiki**：写作时随时查，避免前后矛盾。可用知识图谱或纯 markdown
- **时代背景**：远古、现代、未来、平行世界，决定语言风格与道具体系

### 1.4 人物谱

每个核心角色一张卡片：

- 基本信息：姓名、年龄、外貌、出身
- 性格：MBTI 或更具体的"行为偏好 + 弱点"
- 动机：想要什么、害怕什么
- 口癖 / 标签：让角色"出场即可辨"的特征
- 弧线：从开篇到完本会怎么变
- 关系网：与其他角色的关系强度

**反派尤其重要**：反派要有自己的逻辑闭环，否则后期撑不住。

**主角人设 × 金手指 × 爽点三位一体**（最容易被新手忽略）：

- 苟道流主角 → 必须"低调隐忍 + 厌恶麻烦" → 爽点来自"扮猪吃虎被发现的瞬间"
- 热血/无敌流主角 → 必须"嚣张张扬 + 不服就干" → 爽点来自"当场打脸 + 装比"
- 系统流主角 → 一般"务实功利 + 接受规则" → 爽点来自"任务奖励层层升级"
- 重生流主角 → 一般"沉稳老练 + 略带沧桑" → 爽点来自"信息差碾压"

性格选错爽点出不来。例：让苟道流主角写得很张扬，章末爆点会全部失效。

### 1.5 总纲 + 分卷大纲

- **总纲（500–1000 字）**：主线 + 主角弧线 + 主要冲突。**不必写到结局**，但要写到"前两卷的爽点节奏"
- **分卷大纲**：每卷 30–100 章。每卷必须有
  - 1 个开篇钩子
  - 2–3 个中段爆点
  - 1 个卷末高潮 + 下一卷悬念
- **3–7 卷**是常见结构，太少撑不起百万字，太多容易烂尾

### 1.6 章纲（细纲）

- 每章 200–500 字纲
- **每章一个"钩子 + 爆点"**：开头钩子 → 中段铺垫 → 章末爆点 / 悬念
- **章末钩子比章内内容更重要**——决定读者愿不愿意点下一章
- 工业化做法：先写完一整卷的细纲，再开始铺正文

### 1.7 开局打磨（前 3–10 万字）

投资回报率最高的阶段。**三层死亡漩涡**——每一层失败都会折损一大批读者：

| 关卡 | 读者动作 | 必须做到 |
|---|---|---|
| **前 1000–2000 字** | 决定是否继续读第一章 | **金手指 / 核心钩子必须出现**（3000 字才出在起点 PK 频道几乎必死） |
| **前 3 章** | 决定是否加书架（民间估算流失 70–80%，平台未公布数据） | 前 3 章每章一个小爽点 |
| **前 10 章** | 决定是否追更 | 完成一次"打脸 / 装比 / 装备升级"小爆点 |
| **前 1–2 万字** | 决定签约（起点 2023 改版后，PK 入选 / 签约门槛降低） | 主线冲突已展开、核心配角登场、爽点节奏稳定 |
| **前 10 万字（第 1 卷）** | 决定能否拿到新书推荐位 | 第一次大高潮（突破境界 / 复仇 / 揭秘） |

**关键原则**：前 3 章的密度 > 前 30 章的总和。新手最常见的错误是把"铺垫"放在前 3 章，结果读者根本看不到爆点。

### 1.8 日更连载

- 节奏（按平台分化）：
  - 起点付费文：4000–6000 字/天，重质量
  - 番茄免费文：**单账号中腰部 1–1.5 万 / 天；头部工作室多账号 + AI 辅助常 2–4 万 / 天**
  - 晋江女频：3000–5000 字/天，节奏可稍慢
- **断更 = 高风险**：网文读者忠诚度低，断更会显著掉收藏与追订（具体掉粉幅度因书而异，未有公开统计）
- **AI 日更的真正瓶颈：质量方差**（不是上下文窗口、不是 token 成本）：
  - 同 prompt + 同上下文，连续 30 章会出现 2–3 章**明显劣化**——人物 OOC、节奏崩、违和情绪、用词重复
  - 当前没有可靠的"自动检测劣化"方法——LLM 自审有"自己评自己偏高"的倾向
  - 这意味着无人工兜底的全自动日更，会以 ~10% 概率产出劣质章节，对长期连载是致命的
  - 这才是 §四 把章节正文从 ★★★ 调整为 ★★ 的根本原因

### 1.9 一致性 + 合规维护

包含两块横切关注，每章发布前都要过一遍：

**一致性**（最容易翻车的地方）：

- **时间线**：哪天发生了什么事
- **角色状态**：当前境界、伤势、装备、关系状态
- **设定变更**：哪些设定被修订、被打脸
- **伏笔清单**：埋了什么、什么时候要回收
- **地图**：去过的地方、未探索的区域

> 真正的长篇杀手不是写不出来，而是**自己忘了之前写过什么**。

**合规 / 过审**（AI 生成内容尤其需要）：

- **违禁词检查**（与 AI 无关的常规合规）：政治敏感、色情低俗、暴力血腥、宗教民族、特定历史话题
  - 平台规则差异：起点最严、番茄居中、海外平台较宽
  - 工具层：平台自带敏感词库 + 第三方违禁词检测服务
- **替换术语库**：常见替换（如"做爱"→省略号、特定地名/人名→架空）

**AI 内容真实合规图景**（经一手政策核查，2026-05-19）：

| 层级 | 规则 | 性质 |
|---|---|---|
| 国家《人工智能生成合成内容标识办法》 | 显式标识（文本起始/末尾/中间加文字提示）+ 文件元数据隐式标识 | **要求标识，不是禁止**；2025-09-01 起施行 |
| 阅文 / 起点 | **自己推 AI 工具**（"阅文妙笔"2023-07、"作家助手"集成 DeepSeek-R1 2025-02），政策"鼓励 AI 辅助 + 打击纯 AI 拼凑、洗稿、骗全勤" | 鼓励 + 边界 |
| 晋江 | 2025-02-17《关于 AI 辅助写作使用、判定的试运行公告》——判定"是 AI 辅助还是纯 AI"；禁 AI 生成图作封面；纯 AI 严罚 | 严但不一刀切 |
| 番茄 | 字节系自身大力推 AI 工具；打击批量低质 AI 水文 | 边界 |

**合规边界（简化版）**：

- ✅ **合规**：AI 辅助 + 人类主导剧情/人设/情感 + 标识 + 充分人工修改
- ❌ **违规**：纯 AI 批量生成 + 不标识 + 骗全勤 + 洗稿
- ⚠️ **误判风险**：评论区读者一句"感觉像 AI 写的"有概率触发人工审查 → 文风过于"工整 / 套路"是真实风险

**对项目方向的关键含义**：

- **目标用户没有被合规压缩**——阅文/起点几乎所有作家都在某种程度上用 AI 辅助
- **产品定位必须是"AI 辅助"而非"AI 工厂"**——后者是雷区
- **国家《标识办法》对工具方的义务**：如果做服务提供者形态，需要在生成内容里加显式 + 隐式标识；用户在传播时也要主动声明

### 1.10 读者反馈循环（最反传统的步骤）

- 信号来源：
  - 评论区：剧情吐槽、CP 投票、希望发展方向
  - 追订数据：上架后逐章订阅曲线
  - 打赏 / 月票：高价值读者的强信号
  - 书友群 / QQ 群：核心粉丝的"内部测试"
- 反向调整：
  - 节奏太慢 → 加速推进主线
  - CP 不受欢迎 → 调整戏份甚至换 CP
  - 某配角意外火 → 加戏

> 网文是"边写边改"的，跟传统小说差别最大。**这块曾被定位为 AI 项目的最大差异化机会，但 review 后判定不可行**（persona ≠ 真实读者；真实数据握在平台手里）——详见 §5 方向 B。

### 1.11 上架 / 付费章节

- 上架前 7 天定生死
- 关键设计：
  - **上架卡点**：上架第一章必须是大高潮（突破、复仇、揭秘）
  - **首订冲刺**：动员所有书友群、外站引流
  - **每日订阅曲线**：观察追订留存率
- 数据敏感度：每天看后台，根据数据微调节奏

### 1.12 完本 / 番外 / IP 化

- 收尾：主线闭合 + 主要伏笔回收 + 角色弧线完成
- 番外：满足读者意难平、为 IP 化预留素材
- IP 化：影视、漫改、广播剧、有声书、游戏、海外翻译
- **太监率（行业残酷面，区分口径）**：
  - **签约书完本率约 30–40%**（含烂尾完本）
  - **全平台所有开书的完本率约 10%**（绝大多数死在前 10 万字内）
  - 主要死法：**开局扑街 → AA → 收入跟不上 → 停更**（数据驱动的退出，不是"懒得写"）
- **AI 能压低太监率吗？—— 分情况，不能笼统说能或不能**：
  - 太监的主因链：「数据扑街 → 收入跟不上 → 心态崩 → 弃书」 + 「卡文/创作疲劳 → 失更 → 断更 → 弃书」
  - AI 辅助能解决"卡文 / 创作疲劳 / 节奏失控"这一支——**对一部分太监有效**
  - AI 辅助**不能**解决"数据扑街 → 收入跟不上"这一支——扑街主因是题材选错、爽点节奏不对、读者不买账，AI 辅助不直接改善这些
  - 二阶效应：AI 降低开书门槛 → 总开书量上升 → 整体行业完本率可能下降，但**对个体作者而言，AI 辅助降低创作疲劳是真实价值**
  - **这条对项目的意义**：可以把"对抗创作疲劳 / 卡文 / 节奏失控"作为差异化卖点，但不能笼统宣传"AI 让你不太监"——后者商业上站不住

| 形态 | 配置 | 月产能 | 备注 |
|---|---|---|---|

### 目标用户分层（AI 工具视角）

**这是评估方向 A/B/C 商业可行性的前置问题——不分层后续所有判断都是空中楼阁。**

| 用户类型 | 占比估算 | 主要痛点 | 付费意愿 | 销售周期 | 已有竞品 |
|---|---|---|---|---|---|
| **个人作者**（含爱好者） | 网文圈 ~80% 月收入 0–3k | 卡文 / 节奏感 / 设定一致性 / 起名润色 | < 50–200 元/月 | 短，1–7 天 | **阅文作家助手免费**（DeepSeek-R1 内置） |
| **中型工作室** | 主要在番茄 / 七猫等免费平台 | 写手稳定性、产能放大、爆款复制 | 500–2000 元/座位 | 中，1–4 周 | 工作室自建 / 现有 AI 工具 |
| **平台方**（起点 / 番茄 / 晋江） | 5–10 家 | 合规审查、数据预测、IP 储备 | 大额项目制 | 长，6–12 个月 | 自己定规则、自己做工具 |

**关键判断（基于一手合规核查后校准）**：

- **合规不再是用户群约束**——阅文/起点鼓励 AI 辅助，目标用户是整个网文作家群体
- **真正的约束是竞品**：阅文作家助手免费且功能全（智能问答 / 描写 / 提取 / 画师，每周数十万次调用），独立工具必须有差异化点：
  - 跨平台（不只服务阅文系作者）
  - 更专门化（细分流派 prompt、特定风格库）
  - 更工程化（一致性引擎、状态管理、Claude Code 原生编排）
  - 开源 / 本地化部署（数据隐私）
- 个人作者群体大但 ARPU 低，且竞品免费 → **付费意愿是核心未验证假设**
- 工作室对产能放大有真实付费意愿，但需要 B 端销售能力
- 平台方预算最大，但需要"卖给 B 端 + 数据 / 合规能力"，跟个人项目的产品形态完全不同
- **不能假装"网文创作者"是一类人** —— 文档之后的所有方向评估必须明确"做给哪一类"

## 三、网文 vs 传统小说的关键差异

| 维度 | 传统小说 | 网文 |
|---|---|---|
| 创作周期 | 1–5 年闭门写完 | 边写边发，1–5 年连载（头部更久） |
| 反馈链 | 出版后才有 | 每天每章实时反馈 |
| 篇幅 | 15–50 万字（中文长篇文学常态） | 100–500 万字 |
| 节奏 | 慢热也行 | 必须 3 章内勾住读者 |
| 修改 | 出版前充分打磨 | 已发章节几乎不能改 |
| 商业模式 | 版税 + 实体书 | 订阅 + 打赏 + IP |
| 风险点 | 卖不出去 | 断更 / 烂尾 / 数据扑街 |

**这些差异决定了：把传统小说创作流程直接套到网文上行不通。**

## 四、AI 工作流映射

### 人类角色 → AI agent 对照

| 人类角色 | 对应 AI agent | 主要产出 |
|---|---|---|
| 作者 / 主笔 | Scene Writer / Chapter Writer | 章节正文 |
| 大纲编辑 | Plot Architect / Outliner | 总纲、分卷、章纲 |
| 设定师 | Worldbuilder（带 wiki/向量库） | 世界观文档 |
| 角色管家 | Character Tracker（状态文件） | 角色卡 + 当前状态 |
| 校对 | Continuity Editor / Proofreader | 修订建议 |
| 责编 | Critic / Reviser | 改稿意见 |
| 读者群 | Reader Panel（多 persona 模拟） | 模拟评论、追订预测 |
| 营销 | Blurb / Hook Generator | 简介、章末钩子 |
| 数据分析 | Quality Metrics Monitor | 字数、对话比、节奏分 |

### 工序自动化完成度评估

> 与 §1 速览表的"AI 介入方式"分工：那张表回答"AI 能否主导"（覆盖全部 12 个阶段），下面这张回答"主导/辅助下能做到几分"（仅评 AI 实际能介入的工序）。星级是当前 LLM（2026-05 的 Claude / GPT 体感）实际产出质量，不是理论上限。

| 工序 | 完成度 | 难点 |
|---|---|---|
| 世界观、设定 | ★★★★☆ | 易出"套路化、缺张力"的伪世界观，真正有内在矛盾的设定仍需人工把关 |
| 大纲（总纲、分卷、章纲） | ★★★★☆ | 结构能写出来，但**爽点节奏**和**章末钩子**需人工调 |
| 章节正文 | ★★☆☆☆ | "AI 味"问题在长程下不会随 prompt 优化消失（RLHF 把网文俗气压平了）；**中文网文风格克隆目前无公开成功案例** |
| 一致性维护 | ★★★☆☆ | 向量库能解决"检索相似"，**不能解决"哪里冲突"**；LLM 抽实体变更准确率 70–80%，错一次污染状态。**完整"一致性引擎"不可行，仅适合做半自动辅助** |
| 合规 / 过审 | ★★★☆☆ | 违禁词库可覆盖，但语义级政策风险仍需人工；LLM 自审有"自己评自己偏高"的倾向 |
| 章末钩子设计 | ★★★☆☆ | 模板化钩子容易写，平台读者偏好需数据 |
| 读者反馈循环 | ★☆☆☆☆ | persona 模拟 ≠ 真实读者（LLM 写出的"评论"趋同书评腔，与真实评论区情绪化短评 / 玩梗 / 控评不在一个分布）；**真实评论数据握在平台手里，个人项目拿不到** |
| 上架运营 | ★★☆☆☆ | 需对接平台数据 + 编辑人脉 |
| IP 化对接 | ★☆☆☆☆ | 几乎不可 AI 化（合同、关系、决策） |

## 五、对 ai-lab 项目的启发

> **重要前提**：本节经第 1 轮 agent teams review 大幅修订，原版本"先 C 后 A 最后 B"的依赖排序、以及把方向 B 定位为护城河的判断，已被推翻。

### 重大前置问题（先答这个再谈方向）

**目标用户是谁？**（详见 §二「目标用户分层」）

- 选个人作者：合规天花板低（标注 → 限流），ARPU < 200 元/月，要做"不太监 / 节奏感"
- 选工作室：番茄场景，产能放大是真痛点，付费意愿 500–2000 元/座，但需要 B 端销售能力
- 选平台方：预算大但销售周期 6–12 月，需要"合规审查 / 数据预测"而非"创作工具"

**当前文档建议**：用户分层访谈优先级 > 任何技术方向开工。

### 方向 A：Claude Code Skill —— AI 辅助创作工具（**重定位**）

**重大调整（基于合规一手核查）**：原版本把方向 A 定位为"全自动 AI 工厂 / 工业化流水线"，参考 forsonny/Claude-Code-Novel-Writer 的全自动模式。**这是雷区**——纯 AI 批量生成正是各平台明确打击的对象（骗全勤 / 洗稿 / 低质拼凑）。

**新定位**：AI 辅助 + 人类主导的创作工具，参考样板从 `forsonny`（全自动）换为：

- **阅文作家助手 + DeepSeek-R1**（合法样板，2025-02 上线）：智能问答 / 描写 / 提取 / 画师 4 大功能，每周数十万次调用——但只服务阅文系作者
- **RhythmicWave/NovelForge**（卡片式 + JSON Schema + 人类主导）：跨平台开源样板

**子代理架构（精简，定位为"辅助"而非"主笔"）**：

- 设定 agent（玄幻 / 都市 / 系统流模板库）——辅助世界观构建
- 大纲 agent（按"开篇钩子—中段爆点—卷末高潮"结构）——辅助大纲生成
- 章节 agent（**含章末钩子规则 + 风格特征注入**，风格契约的框架/实例已落地为 skill `skills/novel-style/`）——**生成草稿供人类作者改写**，不直接发布
- 一致性 agent（**事后审查模式**，不实时介入，避免 token O(n²) 爆炸）
- 标识 agent（按《标识办法》自动在元数据 / 章节末尾加 AI 辅助标识）

> 这些子代理各自要吃的"输入契约"（设定 / 角色 / 大纲 / 风格 / 一致性），已统一规划为**开工准备包**，见 `2026-06-01-小说开工准备包全景.md`（含框架/实例分离原则 + 逐块建造路线图，目前 ⑤ 风格层已落地）。

**差异化空间**（vs 阅文作家助手）：

- 跨平台：不只服务阅文系作者（番茄 / 晋江 / 七猫 / 海外华语都能用）
- 更专门化的细分流派 prompt 库（阅文工具偏通用）
- 工程化一致性管理（方向 C）：阅文工具是"功能点"集合，缺整体状态管理
- Claude Code 原生编排：开发者友好、可定制
- 开源 / 本地化部署：数据隐私（部分作者关注）

**风格克隆风险（不变）**：直接克隆头部作者（天蚕土豆、辰东等）有版权与名誉风险。生产化时应该走"提取通用写作特征（节奏、用词密度、对话比）"而非"复刻具体作者"。→ 已落地为 skill `skills/novel-style/`：八维风格契约，框架（刻度轴）稳定、气质实例可换（已含凡人式冷峻 / 热血少年两份示例），抽通用气质而非复刻作者句子。

### 方向 B：读者反馈模拟（**暂不做 / 远期探索**）

> 原版本曾把这条定位为"最大差异化护城河"。第 1 轮 review 之后判定这是**死胡同**，留下记录避免未来重复评估。

**为什么不做**：

- persona 模拟 ≠ 真实读者：LLM 模拟的"评论"高度趋同书评腔，与真实评论区的情绪化短评、玩梗、控评在不同分布
- 5–10 个 persona 覆盖不了真实读者长尾
- 进阶方案"用平台历史数据训练 reward model" —— 数据握在起点 / 番茄手里，**爬取合规问题 + 个人项目拿不到**
- 圈内卷 2 年没人做这块，更可能的解释是 B（做了发现没用）而非 A（没人想到）

**唯一可能的切入**：跟平台方合作拿到数据 → 但那是 to B 项目，不是个人 lab 项目能做的。

### 方向 C：半自动一致性辅助（**从"引擎"限缩为"辅助"**）

> 原版本叫"一致性引擎"，第 1 轮 review 之后判定**完整引擎不可行**（伏笔自动回收 / 百万字一致性 / LLM 抽差量 70–80% 准确率污染状态都是未解决问题）。改为最小辅助形态。

**最小可行实现**（只做这两张表，不做图谱不做状态机）：

- **角色当前状态表**：境界 / 装备 / 伤势 / 关键关系 —— LLM 抽 diff 候选，人工确认入库
- **设定名词表**：已用过的专有名词（地名 / 功法 / 物品） —— 防止前后矛盾、防止名词漂移

**不做**：

- ❌ 完整知识图谱（维护成本爆炸）
- ❌ 自动伏笔回收（没有可靠语义匹配方案）
- ❌ 章节级"差量"提交（git-like 模型在创作流上工作不顺）
- ❌ 语义级合规评分（LLM 自审不靠谱，用违禁词库 + 人工兜底就够）

### 执行顺序（修订版）

**原版**：先 C → 再 A → 最后 B（错的：C 是开放工程难题，先做会卡死）
**新版（加竞品深拆前置）**：**M0 竞品深拆 → A 简版 → C 简版 → B 不做**

1. **M0 竞品深拆（必须先做，1 周）**：阅文作家助手 + DeepSeek-R1 实际能做什么、不能做什么？NovelForge / AI_NovelGenerator / Long-Novel-GPT 的真实使用体感？没有这一步直接开工大概率重复造轮子
2. **方向 A 最简流水线（重新定位为"辅助"，3–5 子代理）**：套现成框架，**1–2 周**跑通端到端
3. **方向 C 简版（两张表：角色当前状态 + 设定名词表）**：跟 A 并行接入，**1 周**实现
4. **跑 10 万字验证**：H1（差异化空间）、H2（质量方差）、H3（用户痛点）
5. **方向 B 不在路线图内**

### 最小可行目标 / 验证 milestone

| Milestone | 周期 | 验证什么 | 通过 / 失败标准 |
|---|---|---|---|
| **M0：竞品深拆 + 用户访谈** | 2 周 | H1 差异化空间 | 找到 ≥ 2 个阅文作家助手没解决的真实痛点 → 通过 |
| M1：A+C 简版跑通 10 万字 | 2–3 周 | H2 质量方差 | 30 章内 ≤ 5% 出现明显劣化 → 通过 |
| M2：5–10 个个人作者试用 | 2 周 | H3 用户支付意愿 | ≥ 3 人愿意付 99 元 / 月（在阅文作家助手免费的前提下）→ 通过 |
| M3：番茄 / 七猫工作室对接 1 家 | 4 周 | 工作室 to B 场景可行性 | 试用后愿意续费 → 通过 |

**任一 milestone 失败都重新评估方向**。**M0 失败（找不到差异化空间）是最严重的——直接砍项目，不要硬撑做"另一个阅文作家助手"**。

|---|---|
| **金手指** | 主角的差异化外挂 / 特殊能力，是网文爽点的来源 |
| **爽点** | 让读者获得满足感的情节高潮（打脸、装比、获得新能力、复仇等） |
| **章末钩子** | 章节结尾留的悬念，决定读者是否点开下一章 |
| **苟道流** | 主角性格低调隐忍，靠"扮猪吃虎被发现"制造爽点 |
| **无敌流** | 主角开局即接近无敌，靠"碾压"制造爽点（中后期写作难度极高） |
| **扮猪吃虎** | 故意示弱后翻盘的桥段模式 |
| **打脸 / 装比** | 让看不起主角的反派当场翻车，主角展示实力 |
| **AA / 扑街** | 数据扑街（订阅 / 收藏 / 推荐严重低于预期），代表作品商业失败 |
| **太监** | 作品中途断更停更（俗称"作者死了"），网文行业最大风险点之一 |
| **追订** | 上架后逐章的订阅数 / 订阅曲线，是付费文最重要的健康指标 |
| **首订** | 上架第一章的订阅数，决定后续推荐位 |
| **均订** | 平均订阅数（VIP 章节总订阅数 / VIP 章节数），按 3000 字算一章 |
| **月票** | 起点等平台读者每月可投的强信号票数，影响月票榜排名 |
| **签约** | 平台与作者签订独家协议，是后续上架 / 分成的前提 |
| **上架** | VIP 化、开始付费章节，是网文商业化的关键时点 |
| **PK** | 起点新书 PK 频道，签约前的曝光场所 |
| **大推 / 封推** | 平台首页推荐 / 封面位推荐，流量翻倍的关键资源 |
| **卡点** | 在关键剧情节点（突破、复仇、揭秘）切章，刺激下一章订阅 |
| **三江** | 起点三江频道，新书重要曝光渠道 |
| **CP** | Couple，配对角色组合，女频和部分男频很在意 |
| **OOC** | Out Of Character，角色行为违反人设——AI 写作长程下最常见的劣化形式 |
