# novel-fingerprint —— 语言指纹 daemon

连续生成网文最先崩的不是人设，是**语言层**：章末收束趋同 + 高频词/句式堆积（实测见
`docs/notes/2026-06-01-fanren连续生成-劣化测试.md`）。⑤ 风格契约是静态的、没记忆，管不住这种
"跨章累积"的漂移。这个脚本就是补这个洞的**纯计算 daemon**——它是 `skills/novel-runtime/`
tick 循环里"语言指纹 store"的实现。

## 为什么是代码不是 prompt

这是四个运行时 store 里**唯一纯机械、无需人工确认**的一个：n-gram 频率是算出来的，确定性的。
其余三个（角色状态/名词表/伏笔）都要"LLM 抽 + 人工确认"，唯独语言指纹是后台 daemon。

## 用法

```bash
node fingerprint.mjs <ch1.txt> <ch2.txt> ... [--names names.txt] [--ends 120] [--min-count 3]
```

- 最后一个文件 = 最新章，与前面的滚动窗口对比。
- `--names`：喂 ⑥ 一致性·表B 导出的**专名+别名表**（见 `fixtures/names.txt`）。
  人名/地名/法宝重复是**预期的、不是劣化**，滤掉才看得见真 tic。这是 daemon 消费 ⑥ 输出的接口。
- 退出码 `2` = WARN（有漂移，喂回 tick 建议改写最新章）；`0` = PASS。

## 它能抓什么、不能抓什么（诚实边界）

| 信号 | 抓得到 | 抓不到 |
|---|---|---|
| 一·跨章重复措辞 | 句式/口头禅 tic（来历不明、不划算、枕席底下…） | 残留通用名词噪声（孩子/东西）——高召回低精度，下游分诊 |
| 二a·章末字面相似 | 章末大段字面复用 | 换了词的趋同（余弦看不见） |
| 二b·章末重复短语 | 章末口头禅（慢慢来、别人没有…） | 同上 |
| —— | —— | **主题层趋同**（"弱肉强食"改写成"强欺弱"）：纯计算测不出，**交 ⑤ LLM 审计兜底** |

定位是**烟雾报警器，不是法官**：surface 候选，由人/⑤审计决定是否真要改写。

## 验证

开发时拿"劣化测试"的连续 3 章跑过：报 WARN，信号二b surface 出 `慢慢来` 章末口头禅、
信号一 surface 出 `不划算/来历不明` 措辞 tic——自动复现了手工发现的漂移。

> 那几章是带版权的小说正文，**未随仓库提交**。自测时把你自己的连续章节放进 `fixtures/`
> （末尾趋同 + 高频词的章节应触发 WARN），并用 `--names` 喂你的专名表（格式见 `fixtures/names.txt`）。
