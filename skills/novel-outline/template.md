# 大纲 · 框架模板（Outline：总纲 / 分卷 / 章纲）

> 这是**框架**，不是某本书的剧情。三级 schema 稳定；每本书填一份**命名实例**。
> 大纲的职责是**调度**——把 ①金手指爽点、②台阶突破、③主角弧线，排进具体章节顺序。
>
> 用法：复制本文件到 `docs/outlines/<作品名>.md`，填好后删除本提示块。

## 2. 分卷骨架

> **每卷四件套必备**：1 个开篇钩子 + 2-3 个中段爆点 + 1 个卷末高潮 + 1 个下一卷悬念。

| 卷 | 境界跨度(接②台阶) | 开篇钩子 | 中段爆点(2-3) | 卷末高潮 | 勾下一卷的悬念 |
|---|---|---|---|---|---|
| 一 | `<如:炼气→筑基>` | | | | |
| 二 | | | | | |
| … | | | | | |

> 「境界跨度」用 ② 设定的力量台阶做尺；「爆点类型」用 ⑤ 风格的单元驱动模型（打脸/危机/探索/情感）。

## 3. 章纲模板（单章三段式）

> 每章一个「钩子 + 爆点」。**章末钩子比章内内容更重要**——它决定读者点不点下一章。

```
第 N 章 · <标题>
├─ 开头钩子：<30字内,一句话拉住读者>
├─ 中段铺垫：<推进剧情/铺爆点>
│   └─（可选）关键节拍 3-5 条：<逐条列中段要发生的具体事件,给生成抓手>
└─ 章末爆点或悬念：<爽点兑现 或 留悬念>  ← 优先级最高
```

> 「关键节拍」是可选档：只写三行钩子-铺垫-爆点时，生成正文中段要临场补很多细节（端到端验证发现）。若想让章节生成更可控，给中段补 3-5 条具体节拍。

工业化做法：先写完**一整卷章纲**再铺正文，别边想边写。

---

## 4. 开局特护（前 10 万字 · 死亡漩涡）

> 投资回报率最高的阶段。**前 3 章的密度 > 前 30 章总和**。每一关卡失败都折损大批读者。

| 关卡 | 必须做到 | 对接 |
|---|---|---|
| 前 1000-2000 字 | **金手指/核心钩子必须出现** | ① 创意层金手指 |
| 前 3 章 | 每章一个小爽点 | ⑤ 爽点密度 |
| 前 10 章 | 完成一次小爆点（打脸/升级/获宝） | ⑤ 驱动模型 |
| 前 1-2 万字 | 主线展开、核心配角登场、爽点节奏稳定（签约门槛） | ③ 配角卡 |
| 前 10 万字（卷一） | 第一次大高潮（突破/复仇/揭秘） | §2 卷一卷末高潮 |

**反面警告**：别把"铺垫"堆在前 3 章——读者看不到爆点就弃书。

## 5. 接口（大纲消费上游、调度全局）

| 来源 | 大纲怎么用 |
|---|---|
| **① 金手指** | 爽点节奏跟着金手指走；开局靠它造钩子 |
| **② 力量台阶** | 排"第几卷突破第几境"，做境界跨度的尺 |
| **③ 主角弧线 + 配角** | 总纲主角弧线引自角色卡；配角登场排进开局 |
| **⑤ 风格 C** | 爽点密度/驱动模型决定每卷爆点的频率与类型 |

---

## 边界提示

- **④ 调度 vs ② 定义 vs ⑥ 登记**：大纲只**调度**"何时突破/何时爆点"；台阶本身在 ② 定义；正文写到后，实际进度进 ⑥ 角色状态表。
- **④ 爆点位置 vs ⑤ 爽点密度**：大纲定"在第几章给爆点"（位置）；风格契约定"爆点多密、什么驱动模型"（密度/类型）。
