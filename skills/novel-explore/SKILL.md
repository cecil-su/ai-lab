# 小说发散前端（Novel Explore · 发散孪生）

把"跟 AI 头脑风暴小说、让它出多个版本我来选、写章前先试写几段定喜好、选中的当后续锚"做成第 8 个 skill。

它是六层准备包（`skills/novel-*`）的**发散孪生**，坐在**最上游**。六层全是**收敛**（每层把模糊感觉逼向一个答案）+ **负向防护**（别漂移/别写崩/别有硬伤），都**假设你已经知道要什么**。explore 补的是它们没有的姿态——"**我有品味、但说不清抽象参数、还在选方向**"。它**不产最终文本，只产被选中的锚**，喂回各层实例文件 / runtime 装配。

> 它不是开工准备包的第 ⑦ 层，是把六层"发散一遍再选"的上游。设计单一来源：`docs/designs/2026-06-02-novel-explore.md`（v0.3，含全档位全景 / 风险 / 连载期接口 / 两轮评审）。

**语言：** 跟随用户，默认中文。

---

## 铁律（先读，违背就别开工）

1. **AI 只发散、绝不排名/推荐"哪个最好"**。只铺选项 + 点差异 + 让人选。（同项目铁律：写手≠审计、AI 不评好坏、读者口不做模拟。这是红线。）
2. **发散必须沿一条有意义的分叉轴**（代价轻重 / 谁是反派 / 主动被动…），否则得到的是 3 个换皮近义物。这步是整个 skill 的含金量，也是最大风险（见 §风险）。
3. **选中的必须落盘成锚** + 在决策记录追加一条流水。锚不落盘 = 白发散。

## 前置 gate：该不该 bake-off（反仪式）

三条判据**全中**才发散；缺一条就别走完整协议：

- ① 这个决策点真有**多个都不错的不同答案**吗？（只有一个显然答案 → 直接定，别凑数）
- ② 你**有品味但说不清**吗？（你已能清楚描述要什么 → 直接填对应收敛 skill）
- ③ 它**锚定大量下游**吗？（孤立的小选择 → 一句话问 AI 即可，不值重型协议）

**铁定不 bake-off**：⑥ 一致性登记（机械抽取+人工确认，没"选哪版"余地）；逐个专名（只 bake 命名**调性**一次，之后按调性生成）。

## 发散协议（高度无关的引擎 · 5 步）

加档位 = 在下方登记表加一行，**这 5 步一行不动**。

1. 聊清这个决策点，**逼出一条有意义的分叉轴**——含金量所在，也是最大风险（提不出真轴就退化成换皮）。**怎么逼**（别只靠灵感、也别只"事后读 3 段看像不像"）：
   - 先列 **3-5 条候选轴**：这个决策点能沿哪些维度变？（例·金手指："机制类型 / 代价轻重 / 成长曲线 / 谁掌握它 / 打破哪个瓶颈"。例·开局："第一钩子类型 / 金手指何时现 / 信息释放快慢"。下方登记表"分叉轴候选"列给了常见档位的现成候选；表里没有的书，照这法子现列。）
   - 挑**最能张成不同空间**的那条——判据：沿它取两个极端值，两个版本要**逼你在下游做互斥的选择**（不同主角性格 / 不同节奏 / 不同读者）。
   - **换皮轴（坏轴）识别**：若两个极端版本除了名字/措辞，下游该填的字段几乎一样 → 假轴，换一条。真轴 = candidates 落到具体字段后逼你二选一；换皮轴 = 选哪个下游都照填、无所谓。
2. 沿轴**并行铺 3-4 个真正不同的版本**。正文轻的（logline / 书名）直接一条消息出 N 版；正文重的（质感/开篇试写，每版一段正文）成本高，可考虑用 workflow `parallel` 跑，起步先 skill 内顺序。
3. **点出版本间差异**（"你在比的是 A 代价高换爆发、B 白给换稳健"），**绝不说哪个更好**。
4. 用户选（允许混搭："要 A 的设定 + B 的口吻"）。
5. **落盘成锚**（按锚类型分流，见下表）+ 决策记录 append 一条流水（选了什么 / 为什么 / 落去哪）。

> **第 5 步不是单一模板**，是按锚类型分流的 dispatch（填字段 / 顶替样例锚块 / append 归档）。所以登记表必须有"落盘动作"列，否则跨文件写一致性会被糊掉。

## 三种锚 × 落盘分流

| 锚类型 | 选的是 | 落到哪 · 怎么写 |
|---|---|---|
| **A 方向锚** | 走哪条路 | ①②③④ 对应实例文件 · **填字段** |
| **B 质感锚** | 读着对的文字 | runtime 装配单 **§2 样例锚行**（`novel-runtime/template.md`）· **顶替** ch1 默认参照片段 |
| **C 卖相锚** | 怎么卖 | `docs/explore/<书>-decisions.md` · **append**（纯归档，无 skill 消费；补搁置的 ⑦ 市场层） |

> 双 sink 行（如感情线落 ③+④、爽点配方落 ⑤+①）：先写主 sink，再校副 sink 既有对齐不被打破，别两边各改一半致接口失谐。

## 阶段 1 三档位详解

### 金手指 + logline（🔴 最高 · 定错全推倒，最先跑）

- **分叉轴**：机制类型（系统/模拟器/苟道/无敌…）× 强度曲线（白给快爽 vs 有代价/成长性的慢热）。逼出"靠什么爽"的真不同，不是换个名字。
- **铺版本**：每版 = 一句 logline（主角是谁 + 金手指是什么 + 主线冲突）+ 一段机制说明 + 强度定位。
- **点差异 / 选**：差异点在"爽点来源 + 长期张力来自成长还是代价"。
- **落盘**：选中版 → 填 `docs/concepts/<书>.md` §1（logline）、§3（机制类型 / 金手指本质）、§4（强度定位 / 成长性 / 代价）。**填完必跑 §5 龙头接口自检**：→③ 主角性格、→② 设定环境、→⑤ 维度C 升级速度、→④ 爽点节奏是否还自洽。破了就回去校。

### 开局策略（🔴 极高 · 第一生死线）

- **为什么压金手指之后第一个跑**：开局是第一生死线——金手指选错能在连载中调强度曲线，**前 3 章把读者赶走无法挽回**（签约门槛前 1-2 万字、太监率全平台 ~90%、"前 3 章密度 > 前 30 章总和"）。
- **分叉轴**：第一钩子类型（危机/悬念/反差/金手指炸场）× 金手指何时登场 × 前 3 章信息释放节奏。
- **铺版本**：每版 = 一份"ch1 怎么开 + 前 3 章节奏"方案。
- **落盘**：选中版 → 填 `docs/outlines/<书>.md` §4 开局特护「关卡」表各行落点（前 1000-2000 字金手指/钩子怎么现、前 3 章小爽点、前 10 章小爆点）。

### 文字质感试写（与开篇场景合流 · 🔴 极高）

- **必须用本书真实开篇/爽点场景**做试写，**不用中性练习场景**——这样一举两得：既当"质感锚探针"，又顺手把"开局优先"做了。
- **分叉轴**：句长 / 抒情度 / 视角距离（同一开篇场景 N 种笔触）。
- **落盘（ch1 锚来源让渡）**：选中片段**顶替** runtime 装配单 §2 样例锚行里 ch1 默认的"参照作品片段"（`novel-style` 模式二 行 102 的回退逻辑）。无 explore 时回退 ⑤ 原逻辑；ch2+ 自举仍归 runtime，explore 仅在拐点显式重置。
- **探针（可选 · 给维护者，非作者必做）**：第一次跑质感试写时顺带对照"多版本选 vs 写一版改一版"，观察记进决策记录——验 #11"发现期多版本选 > 单版迭代"这条零证据前提（详见设计 §八）。

## 阶段 2 方向锚（要点 · 复用协议，不逐档写详解）

阶段 2 全是 A 方向锚，5 步协议照跑、落盘按登记表。只有三个非显然点：

1. **双 sink 档位先主后校**：感情线先写 ③ §6 关系网，再校 ④ 大纲相关 beat 没被打破；爽点配方先写 ⑤ 维度 C，再校 ① §4 强度曲线一致——别两边各改一半致 concept↔style 接口失谐。
2. **爽点配方是"改"不是"铺"**：前置是 ① 金手指已定；它发散的是**兑现密度/节奏**（同一金手指多快给一次爽、给多重），不是平铺选爽点类型（类型已被金手指锁死）。
3. **单章剧情走法可不落盘**：卡文时临时召唤几种戏剧化供选，选完直接写，不一定回填章纲。

> 同 ⚠：阶段 2 这些档位也是**真跑之前的盲建**——分叉轴能否提真轴、落盘咬不咬合，要等真案例验。详解只给阶段 1 三档（探针先压它们）。

## 阶段 3 要点（存疑长尾 · 入表备查，多数不必走重型协议）

阶段 3 的 B/C 档位**全部保留**（用户定"一个都不砍"），但用本设计自己的判据衡量偏弱，诚实标 ⚠存疑·待汰。要点：

- **名场面写法**（B）：与文字质感**同 dispatch**（落 runtime 样例锚块），区别只是**触发在连载拐点**（突破/对决/初遇时重置锚），不是 t=0。
- **视角试写 / 命名调性 / 口癖**（B）：
  - 视角 → ⑤ 维度 A（人称/单多线）。⚠ 网文 95% 第三人称跟随，作者少纠结，多半用不上。
  - 命名调性 → bake **调性一次**（古雅/直白/中二），记进 decisions、之后专名按调性生成。⚠ **无专用消费字段**（⑥ 表 B 只登记已用名词、没有"命名约束"列）——要强约束得给 ⑥/② 加字段（findings F14）。
  - 口癖 → ③ §4 口癖字段。⚠ 下游窄、与 ③/⑤ 重叠。
- **卖相锚 书名/简介/章节标题**（C）：全部 decisions.md append、**纯归档不进装配**。⚠ 关键诚实点：**这三个多数不必走完整 5 步协议**——书名其实一句话问 AI 即可（过不了判据③"锚定大量下游"）。保留只因开书前确有此需求；走**轻量版**（出 N 个、选 1 个、记一笔）就够，别为它启重型 bake-off。

> 阶段 3 入表 = 让登记表完整可查；**不为存疑档位写重型详解**，等消融/实战裁定哪些真是仪式再汰或转正（项目"未实测不删"）。

## 连载期接口（不只 t=0，简）

explore 不是开工用一次就扔，连载期三个时机随时召唤（详见设计 §五）：

- **拐点**（换 POV / 新卷转调）→ 重试质感锚（重置装配样例锚块，ch2+ 自举从新锚续起）。
- **卡文** → 给单章开多版本走法。
- **套路疲劳处方**（连载追读结构防线，**现在就完整可用**）：
  - **触发**：⑤ 模式四"套路疲劳"人工条命中（现有信号，now）；或未来结构指纹自动检测（future，门槛：过 ~20 章 + 消融证明结构有用，现不存在）。
  - **发散 → 落盘**：开 2-3 个"换个 beat"处方（日更姿态压版本数）→ 人选 → 选中 beat 改写进 **④outline §3 对应章纲**（现成 sink，runtime 下一 tick 装配自动读到）。
  - **闭环完整性**：处方落 ④章纲是现成的、不依赖任何新步骤；runtime 若加一个 tick"处方接入"自动步会更顺手，但那是 `novel-runtime` 增强、非 explore 缺口（且排期依赖消融）。

> **连载 vs 日更姿态**：bake-off 与日更速度正面冲突，分两档——**开书前（t=0）一次性密集 bake-off**（开局/金手指/质感锚，定一次管很久）；**连载期只在真卡住时单点召唤、版本压到 2 版**。不区分会变成太监加速器。

## 与现有层的边界（防打架）

| 易混 | explore 的职责 | 现有层的职责 |
|---|---|---|
| 样例锚 | **产**（试写多版本 + 选中） | runtime 装配**消费** + 自举替换。explore 不重造钉锚逻辑 |
| ch1 锚来源 | 有试写 → 选中片段**顶替** ⑤ 默认参照片段 | 无 explore 时回退 `novel-style` 原逻辑；ch2+ 自举归 runtime |
| 大纲分支 | **发散**几条走向供选 | ④ 把选中走向**落成**完整三级大纲 + 校验 |
| 决策记录 | 跨档位"选了什么+为什么"流水账（**纯归档，无 skill 消费**） | 各层实例文件是选定后的成品契约，不记备选 |

## 风险 / 成本（建造时心里有数）

- **最大风险 = 分叉轴提炼**：整个 skill 价值押在协议第 1 步能否逼出真轴。无银弹，靠协议强约束 + 例子示范 + **人当场识别差异**（AI 不许自评）。**建成工具 ≠ 验证通过**——这一步只有拿真案例跑过才知道成不成。
- **成本**：多版本 = N× token，质感/开篇试写尤贵（每版一段正文）。
- **战略定位**：explore 是质量闸消融的**上游、非正交**。不沉淀 runtime 的档位（logline 方向 / 书名）消融管不到、可独立先行；**喂回 runtime 的档位（质感锚 / 大纲分支）依赖消融结论**——若某下游层被判仪式，对应档位作废。

## 设计约束

- **协议不动、加档位只加行**：5 步对所有档位通用；新档位补登记表四格，别给它单写一套逻辑。
- **简单优先**：能一句话问 AI 的别走完整协议（过不了前置 gate 的就别 bake-off）。
- **不替代人类**：AI 只发散，选择权 100% 在人。
