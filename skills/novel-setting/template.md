# 力量体系 / 世界观 · 框架模板（Setting & Power System）

> 这是**框架**，不是某本书的世界。schema 稳定不变；每本书填一份**命名实例**。
> 核心是「力量体系」——网文命脉，读者要能数清主角升了几级、每级强多少。
> 换世界/换书 = 新建实例，框架不动。
>
> 用法：复制本文件到 `docs/settings/<体系名>.md`，填好后删除本提示块。

## 2. 力量体系（核心 · schema 化）

### 2.1 台阶序列（读者要数得清）

> 每一阶必须有**可量化的能力跃迁**（移山/御空/灭城级），不能只写"更强了"。

| 阶序 | 境界名 | 晋级条件 | 代表性能力（量化） | 瓶颈 / 淘汰 |
|---|---|---|---|---|
| 1 | `<如:炼气>` | `<靠什么晋级>` | `<能做到什么,具体>` | `<多少人卡在这>` |
| 2 | | | | |
| … | | | | |

### 2.2 体系元信息

| 字段 | 内容 |
|---|---|
| 台阶总数 | `<太少撑不起百万字,太多读者记不住>` |
| 大/小境界划分 | `<是否每个大境界内还有小层,如炼气1-13层>` |
| 晋级驱动 | `资源积累 / 顿悟 / 战斗历练 / 时间寿元（标主次）` |
| 力量封顶 | `<最高境界是什么,之上还有没有>` |
| 寿元映射 | `<各阶寿命,修仙文常用"卡瓶颈会寿尽"制造紧张>` |

### 2.3 设计自检

- ❓ 台阶读者数得清吗？（经典 5-9 阶为宜）
- ❓ 每阶能力都量化了吗？（不是"变强"而是"能御空/能灭城"）
- ❓ **晋级驱动是否与风格/主角自洽？**——见下方接口

> **接口 · 风格维度 C（节奏）+ ① 金手指 + ③ 主角**：
> - "晋级驱动"要和风格契约的升级速度取值一致：靠资源积累+熬瓶颈 → 慢节奏；靠战斗历练+金手指白给 → 快节奏。
> - 要和主角金手指自洽：金手指若是"催熟资源"，体系晋级就该是"靠资源驱动"。
> - 三者矛盾（如体系设定升级极慢、却给主角快节奏热血气质）会从根上别扭。

## 边界提示（防与别的契约打架）

- **② 定义 vs ⑥ 登记 vs ④ 调度**：本契约**定义**力量台阶与设定；⑥ 一致性底账的「设定名词表」**登记正文里已用过的专有名词**（防漂移）；④ 大纲**调度**主角何时突破。一处定义、一处登记、一处调度，不重复。
- **② 世界规则 vs ⑤ 世界温度**：规则的客观设定在这；读起来的冷暖感觉在风格契约维度 F。
