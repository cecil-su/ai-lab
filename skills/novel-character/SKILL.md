# 小说角色卡（Novel Character Card）

把"写谁"落成可复用、可检验的角色卡。属于**开工准备包第 ③ 层**（全景见 `docs/notes/2026-06-01-小说开工准备包全景.md`）。

**核心设计：框架与角色分离。** `template.md` 的字段是稳定 schema；每个角色填一份命名实例（`docs/characters/<角色名>.md`）。一本书 = 多份实例卡。

**语言：** 跟随用户，默认中文。

## 两种模式

| 模式 | 干什么 | 触发 |
|---|---|---|
| **建卡**（默认） | 产出/修订一份角色卡实例 | "建个角色""写主角/反派卡" |
| **盘点**（可选） | 对整组角色做一致性体检 | "盘一下人物""查查角色有没有问题" |

---

## 模式一 · 建卡

### Phase 0：确定角色定位
先问/确认这个角色是 **主角 / 核心反派 / 重要配角 / 功能配角**——定位决定填多深：
- 主角：全字段，**§7 三位一体必填**
- 核心反派：全字段，**§8 逻辑闭环必填**
- 重要配角：基本信息+性格+动机+关系网，弧线选填
- 功能配角：一句话标签 + 必要信息即可，别过度设计（YAGNI）

### Phase 1：逐节填卡
读 `template.md` 拿字段。一次推进 1-2 节，不要一次抛全表。重点：
- **§2 性格**：必须能预测"遇事怎么做"，且**必须有致命弱点**——无缺陷的角色立不住。
- **§3 动机**：表层目标 + 深层恐惧 + 底线，决定角色会往哪走。

### Phase 2（仅主角）：三位一体自洽
填 §7，做自检：**人设取向 × 金手指 × 爽点**三者必须互相支撑。
- 苟道流人设配"扮猪吃虎"爽点；热血人设配"当场打脸"爽点。错配则章末爆点失效。
- 填不自洽就停下，让用户调人设或调金手指/爽点，别硬写。

### Phase 3（仅主角）：投影到风格契约
把 §7 人设取向投影到风格契约维度 B（决策驱动/行为姿态/风险偏好）。
- **若该书已有风格契约实例**（`docs/styles/*` 或 `skills/novel-style/examples/*`），核对投影是否一致；不一致就指出"卡片和风格契约有一个要改"，请用户定夺。
- 参考对齐示例：`examples/hanli.md` §7 ↔ `../novel-style/examples/fanren.md` 维度 B。

### Phase 4（仅核心反派）：逻辑闭环
填 §8：反派目标在他自己逻辑里要成立，给他一个自己信服的动机，别写成工具人。

### Phase 5：存盘
1. 文件名用角色名 slug。
2. 复制 `template.md` 结构填好，写入 `docs/characters/<slug>.md`（目录不存在则创建）。
3. 删模板提示块。

参考填好的实例：`examples/hanli.md`（主角）。

## 模式二 · 盘点（可选）

读 `docs/characters/` 下全部卡 + 该书风格契约，做一次体检：

1. **主角三位一体**：是否自洽？投影是否与风格契约维度 B 一致？
2. **反派逻辑**：核心反派有逻辑闭环吗？还是工具人？威胁与其能力/资源匹配吗？
3. **关系网**：关系是单向登记还是双向闭合？有没有"提到却没建卡"的角色？
4. **弧线**：主角有完整弧线吗？重要配角是否纯背景板？
5. **与设定层接口**：角色的出身/能力是否在 ② 设定层（力量体系/势力图）里站得住？

输出：问题清单 + 具体到哪张卡哪一节 + 修补方向（不直接代写）。

> 同 `novel-style` 的审计：这是辅助信号，需人工拍板，不是自动门禁。

## 文件与边界

| 文件 | 作用 |
|---|---|
| `template.md` | 角色卡框架·稳定 schema（不要改字段轴） |
| `examples/hanli.md` | 韩立（主角）填好实例，与 fanren 风格契约对齐 |
| `docs/characters/<slug>.md` | 用户产出的角色卡实例（每角色一份） |

**关键边界**（来自全景文档"重叠与边界"表）：
- 角色卡 = 稳定设定 + 弧线；**当前境界/装备/伤势属 ⑥ 一致性底账的状态表**，不写进卡。
- 主角性格全身像在本卡 §7；风格层只取"维度 B 投影"。**先定卡，再投影到风格契约。**

## 链路
- **上游**：① 创意层（金手指）→ 喂 §7；② 设定层（力量体系/势力）→ 约束角色能力出身。
- **下游**：角色卡随 ⑤ 风格前缀一起作为上下文喂给章节生成；状态实时值进 ⑥ 状态表。
