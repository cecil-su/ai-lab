# 小说风格契约（Novel Style Contract）

把"我想写得像某本书"这种模糊感觉，拆成**可执行、可检验的参数**，产出一份可复用的风格契约，并注入到章节生成中。

**核心设计：框架与气质分离。**

- **框架**（`template.md` 的八维刻度轴）= 稳定常量，永不随气质变动。
- **气质** = 在框架里填一组取值，存成一份命名实例（`docs/styles/<气质名>.md`）。
- 换气质 = 复制模板、重填取值，框架和本工作流一行不动。

**语言：** 跟随用户，默认中文。

## 三种模式

| 模式 | 干什么 | 触发 |
|---|---|---|
| **定义**（默认入口） | 产出/修订一份风格契约实例 | "定义风格""像XX那样""新建一个气质" |
| **注入**（默认随定义） | 把契约转成 prompt 前缀，喂给章节生成 | "用这个风格写""注入风格" |
| **审计**（可选） | 拿一段正文反查是否跑味 | "检查这段跑味没""审一下风格" |

定义完成后默认引导到注入；审计仅在用户明确要求时进入。

## 模式一 · 定义

### Phase 0：确定入口路径

先问用户走哪条路（二选一）：

- **路径 A（有参照作品）**：用户给了一本/几本参照书 → 做"风格解剖"，逐维度反推取值。
- **路径 B（只有想要的感觉）**：用户只描述了想要的气质 → 直接定义取值。

如果用户已说清楚（如"像凡人修仙传"=路径 A），不必再问，直接开工。

### Phase 1：逐维度填取值

读 `template.md` 拿到八维框架。对每个维度，**一次只推进 1-2 个维度**，不要一次抛完八维让用户懵。

- **路径 A**：让用户给 2-3 个最有代表性的片段（或凭印象描述），**逐句反推**"这句体现了哪个维度的什么取值"，把感觉落到刻度轴上。反推比凭空定义准得多。
- **路径 B**：用刻度轴做选择题问用户，把模糊气质逼成具体取值。

每个维度填两样：**取值**（落在轴上的位置）+ **理由**（为什么这个气质要这个取值）。

> 维度 B（主角性格基调）是全书指纹，花最多力气。其余维度可以快一些。

### Phase 2：禁忌清单（最关键的防跑偏）

填完八维后，专门做禁忌清单。提醒用户：**LLM 默认会写得更爽、更热血、更抒情、更上帝视角**——禁忌清单就是堵这些默认倾向。每条尽量具体到"可判定真假"。

### Phase 3：主角试金石

凝练成一句"遇事时主角会怎么做/怎么说"的判据。这是后续审计的单点检验器。

### Phase 4：存盘

1. 从气质名推导文件名 slug（小写、a-z 0-9 连字符）。
2. 复制 `template.md` 的结构，填好取值，写入 `docs/styles/<slug>.md`（目录不存在则创建；已存在追加 `-1`）。
3. 删除模板顶部的提示块。
4. 告诉用户：契约已存盘，可随时复制另存来派生新气质。

参考已填好的实例：`examples/fanren.md`。

## 模式二 · 注入（默认随定义之后）

把一份契约实例转成**可直接放在章节生成 prompt 最前面的风格前缀块**。

### 产出格式（正面定义 + 禁忌清单）

```
【风格契约：<气质名>】
视角：<维度 A 取值浓缩成一句>
主角：<维度 B 取值浓缩，强调决策依据>
节奏：<维度 C 取值浓缩>
语言：<维度 D 取值浓缩>
冲突：<维度 E 取值浓缩>
世界：<维度 F 取值浓缩>
信息：<维度 G 取值浓缩>
禁忌：<禁忌清单逐条，这是 negative prompt，最重要>
试金石：<一句话判据>
```

要点：

- 把八维表压缩成**短句**，不要把整张表塞进去——前缀越长越稀释。
- **禁忌清单一条都不能省**，它对抗 LLM 默认倾向的作用最大。
- 这个块作为**固定前缀**，拼在每章的章纲/上下文之前，再让章节 agent 生成。

> 衔接：这正是 `docs/notes/2026-05-19-网文创作流程与AI角色映射.md` §四 提到的"风格特征注入"。
> 章节 agent 生成草稿供人类改写，不直接发布（合规定位见该文档 §1.9）。

## 模式三 · 审计（可选）

拿一段已生成的正文，对照契约逐维度反查是否跑味。

### 流程

1. 读契约实例 + 用户给的正文片段。
2. **先过主角试金石**：这段里主角的行为/台词，符合试金石吗？不符合直接标红——这是最快的跑味信号。
3. 逐维度打分：每个维度标 ✅符合 / ⚠️偏移 / ❌违背，违背的引用原文具体句子。
4. 重点查禁忌清单：是否踩了任何一条 ❌。
5. 输出：跑味维度清单 + 具体证据句 + 改写方向（不直接代写整段，给方向）。

> 这呼应该研究文档 §1.8 的 OOC/劣化检测痛点——但注意文档结论：LLM 自审有"自评偏高"倾向，审计结果是**辅助信号，需人工兜底**，不能当全自动门禁。

## 文件

| 文件 | 作用 |
|---|---|
| `template.md` | 框架·空白八维 schema（稳定常量，不要改刻度轴） |
| `examples/fanren.md` | 凡人气质的填好实例（示范框架/实例分离） |
| `docs/styles/<slug>.md` | 用户产出的命名实例（每种气质一份） |

## 设计约束

- **不改框架轴**：维度和刻度轴是稳定层。要新增维度先确认它对所有气质通用，否则放进具体实例的备注里。
- **简单优先**：八维够用就别加维度；契约前缀够短就别堆。
- **不替代人类**：定位是"AI 辅助"，审计是辅助信号不是门禁。
