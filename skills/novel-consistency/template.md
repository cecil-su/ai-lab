# 一致性底账 · 框架模板（角色状态表 + 设定名词表 + 伏笔台账）

> 这是**框架**（三张表的 schema），不是某本书的内容。和别的层不同：这是**边写边维护的底账**，记"当前实际值"，开工时建空表，每章写后增量更新。
> 目的：对抗长篇真正的杀手——**作者自己忘了之前写过什么**。
>
> 用法：复制本文件到 `docs/ledgers/<作品名>.md`，开工时按 ②③ 填初始值，之后逐章更新。删除本提示块。
>
> **铁律**：LLM 抽变更只有 70-80% 准确率，错一次污染全表。**只用 LLM 抽候选，人工确认才入库。**

## 表 C · 伏笔台账

> 对抗另一个长篇杀手——**埋了的钩子忘了回收**（悬空的"读者期待"）。每条伏笔是一张带"回收窗口"的工单：开 → 已回收 / 弃用。
> **铁律**：「是不是伏笔」是**作者意图**，文本测不出——LLM 抽不出，只能**到期提醒**。**人工登记**才入账。

| 伏笔 | 埋设章 | 预期回收窗口 | 状态 | 回收章 | 备注 |
|---|---|---|---|---|---|
| `<埋了什么钩子>` | | `<如:卷二中 / 第80章前>` | 开/已回收/弃用 | | `<给读者的预期是什么>` |

> 状态：**开**=欠着未还；**已回收**=填回收章；**弃用**=主动放弃（要确认读者不会追问）。

## 维护流程（每章写后）

1. **抽候选**：让 LLM 从新章里抽三类候选——①状态变更 ②新出现专有名词 ③伏笔（本章埋了什么疑似钩子 / 回收了表 C 哪条）。
2. **人工确认**：逐条核对——确认无误才更新表 A / 追加表 B / 登记表 C。LLM 抽错会污染状态，不许自动入库。**伏笔尤其靠人工判**：LLM 说"疑似伏笔"，作者决定立不立账。
3. **写新章前查表**：开写下一章前查表 A（主角当前境界/伤势）、表 B（避免名词漂移）、**表 C（哪些伏笔到了回收窗口，该还了）**。

## 边界提示

- **⑥ 登记 vs ② 定义 vs ③ 设定 vs ④ 调度**：
  - ② 定义力量台阶（设计）；④ 调度何时突破（计划）；**⑥ 登记主角此刻在第几境（实际值）**。
  - ③ 角色卡记稳定人设/弧线；**⑥ 表 A 记会变的当前境界/装备/伤势**。
- 不做：完整知识图谱、**自动伏笔回收判定**（表 C 只人工登记 + 到期提醒，回收与否人决定）、语义级合规评分（研究文档 §五方向C 判定不可行）。**只维护这三张表。**
